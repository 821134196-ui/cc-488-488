# 社区棋牌室 · 桌台预约与牌具清点系统（演示）

纯 Python 标准库实现（无需安装依赖）：SQLite 持久化、内置 HTTP 服务、进程内后台任务、
模拟门锁与付款适配器。会员、金额均为演示数据。

## 一条命令启动

```bash
python3 run.py              # 重建演示数据（续时冲突/少件/换桌等样例）并启动
# 打开 http://127.0.0.1:8000
```

其他参数：`--port 8080`、`--clean`（不生成样例）、`--no-scheduler`。

## 测试

```bash
python3 run_tests.py        # 零依赖测试运行器（环境装有 pytest 时也可直接 pytest）
```

覆盖：桌台+牌具**双锁**并发、**并发开场只允许一次**、**续时边界**（端点相接/冲突留痕）、
开场与散场**清点差异**（缺件空框、跨场借件未还计少件）、**清洁阻断**（未清洁不能预约/开场）、
**退款/赔付幂等**、减免须社区负责人、提醒幂等、HTTP 端到端冒烟，共 32 项。

## 八个界面

| 路径 | 界面 | 说明 |
| --- | --- | --- |
| `/` | 场地平面图 | 1 米=42px 等比绘制保持真实间距；桌号圆圈，预约条直接贴在桌号下方 |
| `/calendar` | 桌台日历 | 按桌台行展示当日预约条，颜色区分状态 |
| `/book` | 预约登记 | 确认后同时锁定桌台与牌具、预收茶水押金 |
| `/open/<id>` | 开场清单 | 按套装展开固定数量格（棋子/牌张/计时器逐格），缺件保留红色虚线空框 |
| `/inventory` | 牌具库存 | 套装固定构成、占用场次、最近清点差异 |
| `/timer/<id>` | 计时端 | 只显示剩余时间与 +30/+60 续时、散场三个高频操作 |
| `/close/<id>` | 散场核验 | 实际时长 15 分钟进位计费、逐格清点、损坏照片、争议挂起 |
| `/cleaning` | 清洁队列 | 待清洁→清洁中→完成；完成前台桌才可再用 |
| `/review` | 结算复核 | 账单与收退款流水（幂等键）；赔付收取/减免审批 |

右上角可切换身份：**前台 / 管理员 / 社区负责人**。仅管理员可临时调桌；
赔付减免仅社区负责人可批准。

## 业务规则

- 预约确认即对桌台与牌具双锁；迟到 15 分钟未开场由后台任务自动释放双锁并记录。
- 开场为 CAS（`booked→seated`），并发开场只成功一次；开场少件逐格留痕。
- 续时不得与后续预约重叠（端点相接允许），冲突被拒绝并记录“续时冲突”。
- 散场按实际时长计费；牌具完整 → 收款/退押金（幂等）→ 释放双锁 → 待清洁。
- 少件、借件未还、赔付争议：桌台与牌具**保持锁定**，清洁暂缓，复核放行后才进入清洁。
- 茶水泼洒、设备故障、跨场借件、临时换桌、赔付争议均写入事件流水。
- 损坏照片保存在本地 `photos/`；数据库在 `data/chessroom.db`。

## 目录结构

```
chessroom/
  db.py          SQLite schema 与事务（BEGIN IMMEDIATE + 进程内串行锁）
  catalog.py     房间/桌台/牌具套装/会员演示目录
  adapters.py    模拟门锁、模拟付款（幂等键 + 退款余额保护）
  services.py    预约/开场/续时/换桌/借件/清点/赔付/清洁/结算 业务服务
  scheduler.py   进程内任务：迟到释放、开场提醒
  web/           HTTP 路由、服务端渲染页面、静态资源
run.py           启动入口 + 演示样例生成器
tests/           32 项测试
```
